# 2B 行业模块

## 行业特征

- 客户为企业，决策链长（采购→IT→业务部门）
- 收入模式多元：订阅制（seat-based / usage-based）、按效果付费（outcome-based）、AI 原生定价（token/query-based）
- 不只限于 SaaS——AI 原生 2B 服务可能绕过传统 SaaS 形态，直接以 Agent、API、结果交付等形式存在
- 基模威胁：Agent 绕过 UI、压缩 seat 数、替代中间层软件、让"功能优势"半衰期急剧缩短

## 核心概念：你的护城河是燃料还是灰烬？

传统护城河是一道静态的墙。逃逸理论不问"墙有多高"，而问"你能跑多快"。

| 排名 | 燃料类型 | 静态视角（传统护城河） | 逃逸视角（加速度来源） | 强度 |
|------|---------|---------------------|---------------------|------|
| 1 | 闭环数据飞轮 | 我有别人没有的数据 | 每次使用都产生新的专有信号，让系统越来越好——基模升级不能复制你的客户特定数据 | 最强 |
| 2 | 工作流深度嵌入 | 切换成本高 | 每多嵌入一层，客户换掉你的痛苦就指数增长——基模越强，企业越需要能"兜底"的稳定运行环境 | 非常强 |
| 3 | 分销与品牌 | 获客成本低 | 信任随时间复利——在"足够好"的 AI 产品泛滥时，分销决定谁被看见 | 强 |
| 4 | 可靠性与信任 | 系统稳定 | 每次正确交付都在累积信任资本——AI 幻觉泛滥的时代，稳定就是稀缺品 | 中强 |
| 5 | 合约与合规 | 客户走不了 | 合同条款是法律加速器——在技术护城河失效时提供缓冲时间；合规认证是受监管市场的准入壁垒 | 中等 |
| — | 功能优势 | 产品更好 | **基模升级一次就可能归零——这是最弱的燃料，因为它会燃尽** | 最弱 |

> 🔥 **为什么功能优势是"会燃尽的燃料"？** 2022 年需要 18 个月、300 万美元构建的能力，2026 年用基础模型 60-90 天就能复制。（来源：Value Add VC, 2026）功能优势的半衰期在急剧缩短。如果你唯一的燃料是功能，每次基模升级都会烧掉一截。

## 评分维度（8 维度 × 加权）

### 正向逃逸燃料（满分 75）

#### 1. 闭环数据飞轮（权重 ×2.5，满分 25）

**核心判断**：这是最强的逃逸引擎——但"有数据"本身不是护城河，数据只有在闭环中才产生加速度。

闭环飞轮需要**三个条件同时满足**：
1. 产品使用产生有价值的模型改善信号
2. 信号是专有的、无法从公开来源复制
3. 改善的模型驱动更好的产品体验 → 更多使用

**打分标准**：

- **9-10 分**：闭环飞轮完整运转——使用→独特信号→模型改善→更好体验→更多使用。数据具有法律独占性或物理不可复制性。典型如 Jenni.ai 的学术引用数据库（每多一个用户上传 PDF、修正建议，系统对学术写作"正确性"的理解就深一层，通用模型在公共互联网上永远学不到）
- **7-8 分**：有明显数据积累和改善信号，但飞轮未完全闭环（如某环节依赖人工标注）
- **4-6 分**：有一定数据积累但可被竞品通过其他渠道部分获取
- **1-3 分**：无明显专有数据积累，或数据量虽大但不产生改善信号

**关键追问**："客户使用你的产品时，产生了什么公开互联网上不存在的数据？这些数据是否让下一次服务更好？"

---

#### 2. 工作流深度与转换成本（权重 ×2.0，满分 20）

**核心判断**：你每多嵌入一层（身份认证、计费、CRM、审批流、数据管道），客户换掉你的痛苦就增加一个数量级。这不是靠"锁定"，而是靠"积累"——客户不想走，不是因为走不了，而是因为走了会变差。

**逃逸视角拆解**：

| 嵌入层 | 切换痛苦 | 案例 |
|--------|---------|------|
| 身份认证 + SSO 集成 | 低——重新配置账号体系 | 所有 SaaS |
| 计费 + 支付集成 | 中——财务流程中断 | Stripe 级集成 |
| CRM + 数据管道 | 高——数据迁移 + 流程重建 | Salesforce |
| 审批流 + 合规审计 | 极高——6 个月运营痛苦 | Veeva、Procore |
| 全栈系统（system-of-record） | 不可逆——业务无法运转 | SAP、Oracle |

**打分标准**：

- **9-10 分**：System-of-record——替换 = 6 个月以上运营中断，客户业务深度依赖
- **7-8 分**：有较深集成但核心流程仍可绕开，切换需要 1-3 个月
- **4-6 分**：有一定集成度，但替换成本可控在数周内
- **1-3 分**：独立工具型，切换成本极低（导出数据→导入竞品→当天继续工作）

**关键追问**：
- "如果你的服务宕机一周，客户业务会受到多大影响？"
- "客户是来用'工具'的还是来建'系统'的？——工具可以换，系统换不了"

---

#### 3. 分销与品牌（权重 ×1.5，满分 15）

**核心判断**：分销是网络效应的起点——每一次获客都让下一次获客更便宜。内容、社区、品牌、SEO 需要 18-24 个月复利，但一旦建立，竞争对手在 12 个月内无法复制同等成本优势。在"无限好的 AI 产品"泛滥的市场中，**分销决定谁被看见**。

> ⚡ **AI 时代的时序重构**：传统 SaaS 的节奏是"打磨产品 → 找到 PMF → 规模化分发"——但在 AI 时代，等 PMF 确认了再铺分销，窗口已经关闭。基模 3-6 个月一次大升级，赛道每个月都在重新洗牌。**Day one 就开始获客、获得收入、与用户共创**，才是正确的节奏。产品本身就是在客户的生产环境中长出来的，而不是在车库里磨出来的。

**逃逸视角**：分销不是一次性广告投放，而是**可复制、可规模化的获客引擎**。最理想的状态是"用户共创"——早期客户不仅付钱，还参与定义产品方向，他们的反馈直接塑造产品路线图，形成"越早用越有话语权"的正向激励。Jenni.ai 的短视频矩阵是典型案例（可复制的内容获客引擎），但更深的壁垒是"用户共创"本身——第一批付费客户在产品里留下了他们的 workflow 痕迹、偏好数据、定制配置，这些东西他们换一个竞品就要全部重来。

**打分标准**：

- **9-10 分**：Day one 就建立了获客+收入+共创的飞轮——客户一边付钱一边帮打磨产品。获客成本持续下降，自然流量占比高，收入从一开始就是产品迭代的指南针
- **7-8 分**：有明确增长引擎且部分渠道验证有效，有早期共创客户但规模有限
- **4-6 分**：先打磨产品再考虑分发，客户获取滞后于产品开发。或增长主要靠投放/销售团队线性驱动
- **1-3 分**：无分发策略，在"等产品好了再推"的思维里——这意味着产品可能永远等不到"好"的那天，因为窗口在关闭

**关键追问**：
- "你第一天就在卖吗？还是还在'打磨产品'？——如果是后者，窗口还剩多少？"
- "你的早期付费客户在产品里留下了什么他们换不走的东西？"
- "不烧钱投放的情况下，用户能找到你吗？自然流量占比多少？"

---

#### 4. 可靠性与信任积累（权重 ×1.0，满分 10）

**核心判断**：信任建立慢、失去快。在 AI 产品频繁出现幻觉和漂移的当下，能**稳定交付正确结果**的产品，每一次正确交付都在累积信任资本。这不是基模能通过一次升级就覆盖的——它需要的是在真实生产环境中的长期验证。

**逃逸视角**：可靠性是信任的复利机器。可靠性打开了更深的企业采纳——当客户信任你的输出时，他们会把更重要的任务交给你，这会带来更多数据和更深嵌入，形成正向循环。

**打分标准**：

- **9-10 分**：长期生产验证（≥2 年），有明确 SLA 保障，在关键任务中建立了"不会搞砸"的口碑
- **7-8 分**：较强可靠性记录但时间不足（<2 年），或 SLA 覆盖范围有限
- **4-6 分**：基本可用但有已知的边界 case，偶有错误需要人工兜底
- **1-3 分**：稳定性存疑，无 SLA，或频繁出现幻觉/错误

**关键追问**："客户有没有把'搞砸了会很严重'的任务交给你？如果有，说明信任已建立；如果全是低风险任务，说明信任还没到。"

---

#### 5. 合约与合规锁定（权重 ×0.5，满分 5）

**核心判断**：合约条款是法律加速器——在技术护城河失效时，合约提供了缓冲时间。合规认证（SOC 2、HIPAA、FedRAMP）需要数年和数百万美元才能获得，在受监管行业（医疗、金融、法律、政府），合规是基模厂商无法快速跨越的门槛。每提前一天通过认证，就多一天的先发优势。

**逃逸视角**：这不是"锁死客户"，而是"争取时间"——合约为你赢得的时间窗口，应该用来加速积累真正复利的燃料（数据飞轮、工作流嵌入），而不是躺在合约上睡觉。

**打分标准**：

- **9-10 分**：多年合同（≥2 年）+ 深度合规认证（如 FedRAMP、HIPAA），合规是行业准入门槛
- **7-8 分**：有多年合同或关键合规认证之一，客户有明确的合约约束
- **4-6 分**：年付合同为主，基础安全认证（SOC 2），合约约束力有限
- **1-3 分**：月付/即用即走，无合规认证，客户随时可离开

**关键追问**："如果明天基模厂商推出跟你一样功能的产品，你的合约和合规认证能给你争取多长时间的缓冲？在这段时间里你能做些什么？"

### 负向风险扣分（满分 -30）

#### 6. 会燃尽的燃料依赖（权重 ×-1.5，扣分上限 -15）

**核心判断**：以下五件事在 2026 年已经不再是护城河，因为它们会在基模升级中瞬间燃尽（来源：Mavik Labs, 2026）：

| 常见误解 | 为什么会燃尽 | 燃尽时间 |
|---------|------------|---------|
| "我们用最好的模型" | 竞争对手也可以切换模型；模型能力在快速商品化 | 下一次模型发布 |
| "我们有提示词" | 提示词极易被逆向工程和复制 | 数周 |
| "我们有微调" | 微调优势随着提供商追赶而迅速扩散 | 数月 |
| "我们有 UI" | UI 可以在几天内被克隆 | 数天到数周 |
| "我们有大量数据" | 数据量 ≠ 结果质量；公开可获取的数据无独占性 | 取决于数据来源 |
| "我们成本更低" | 如果你的成本优势来自基模厂商的降价——那是人家的成本改善，不是你的。下一次涨价你也得受着 | 下一次模型定价调整 |

这些"燃料"的共同特征是：**它们的价值依赖于基模当前的能力缺口**。当基模填补了缺口，这些价值就归零。Forefront Chat 的免费 GPT-4 访问、ChatPDF 的文档对话、Tome 的 AI 演示——它们都是在基模的某一层缺口上建立的，缺口一填，整个价值主张就蒸发了。

> ⚠️ **第六条"成本优势"尤其隐蔽**——很多创业公司把基模厂商的 API 降价当成了自己的护城河。如果你不拥有模型，你就没有"成本端的学习曲线"。详见维度 8（商业模式脆弱性）中的"按结果付费 × API 成本悖论"。

**打分标准**：

- **9-10 分（极高风险）**：核心价值完全建立在基模能力缺口上——仅调用 API + 简单 UI + 公开提示词，基模升级后归零
- **7-8 分（高风险）**：有工程化封装但核心差异化来自基模当前的能力短板，基模升级后大部分价值被覆盖
- **4-6 分（中风险）**：有自研模型或深度微调，但核心能力路径仍依赖特定基模版本
- **1-3 分（低风险）**：核心价值来自专有数据/工作流/合规等"慢变量"，基模升级不会动摇根本

> 🔥 **大科技竞争对手测试**："如果 OpenAI/Anthropic 在 6 个月内发布你的产品原生版本，客户有多少会留下来？"
> - 只能指出"产品质量更好"→ 高风险
> - 能指出工作流深度、数据独占性 → 中风险
> - 替换 = 6 个月运营痛苦 → 低风险

**CB Insights 数据**："被资源更充足的竞争对手击败"是 AI 创业失败的第二大原因（仅次于资金耗尽），而这些失败大多因为创业公司的唯一优势是产品质量——更大的团队可以用 10 倍的资源复制同样的质量。（来源：Value Add VC, 2026）

---

#### 7. 赛道结构风险（权重 ×-1.0，扣分上限 -10）

**核心判断**：赢家通吃型赛道的创业公司天然处于劣势——通用 AI 编码、AI 搜索、AI 办公助手、通用 Agent 平台已被大厂重兵布局。

| 赢家通吃（高危） | 生态多样（安全） |
|:---|:---|
| 通用 AI 编码、AI 搜索、AI 办公助手、通用 Agent 平台 | 垂直行业 Agent、合规型垂直 SaaS、AI 出海、细分工作流 |

**打法标准**：

- **8-10 分**：赢家通吃型赛道，大厂已重兵布局且产品形态高度趋同
- **5-7 分**：有巨头进入但项目已找到明确利基，或赛道天然碎片化
- **1-4 分**：赛道碎片化、巨头不愿进入，或项目已形成局部垄断

---

#### 8. 商业模式脆弱性（权重 ×-0.5，扣分上限 -5）

**核心判断**：2B AI 创业正在形成一个结构性矛盾——客户越来越期望按结果付费，但如果模型不是自己的，成本端你说了不算。

---

**核心悖论：按结果付费 × API 成本悖论**

```
客户期望：按结果付费（"你给我正确输出，我才付钱"）
            ↕ 根本矛盾
创业公司现实：按 token 付钱给基模厂商（"客户每用一次，我就欠一笔 API 费"）
```

这不仅是一个"定价策略问题"——它直接决定了**你拥有什么燃料**：

| 成本结构 | 收入模式 | 逃逸含义 |
|---------|---------|---------|
| **自有模型** + 按结果收费 | 边际成本趋近 GPU 推理成本，用量越大单次越便宜 | ✅ **规模经济 = 逃逸燃料**——你的成本曲线在往下走 |
| **调用第三方 API** + 按结果收费 | 边际成本 = API 定价（别人说了算），用量越大…利润可能越低 | ❌ **你不拥有自己的成本曲线**——用量增长不产生规模经济 |
| **调用第三方 API** + 按 seat 收费 | 两边脱钩——seat 收入和 token 成本不对齐，一个 heavy user 吃掉十个 seat 的利润 | ❌ **双重错配**——收入按人头算，成本按用量算，两者不同步 |
| **调用第三方 API** + 按 token/用量收费 | 转手买卖——中间商赚差价，价差就是你的全部利润空间 | ⚠️ 勉强对齐但利润薄——基模厂商稍微涨价或客户压价就归零 |

> 🔥 **关键问题**：如果你不拥有模型，你就没有"成本端的学习曲线"。基模厂商降价时你偶然得利，但那是**人家的**成本改善——不是你的结构优势。下一次涨价你只能被动承受，而且随着模型能力提升，客户使用的 token 量可能暴增，你的毛利反而被吃掉。

**为什么这件事在 2026 年尤其紧迫？**

1. **行业共识在往按结果付费走**——Redpoint、a16z、Bessemer 都在推动 outcome-based pricing，客户也已经开始默认"你应该按效果收我的钱"
2. **但大多数创业公司并不拥有模型**——他们夹在中间：收入端承受"按效果付费"的压力，成本端承受"按 token 付费"的现实
3. **基模厂商有动力吃掉"结果溢价"**——如果你只是在基模基础上做了一层薄薄的工程封装实现"按结果交付"，基模厂商完全可以自己做这层封装，然后把"结果"也纳入 API 定价。届时你既失去了差异化，也失去了价格空间

**谁日子好过？**

- **自有模型 / 深度微调 + 按结果收费**：成本曲线往下，收入曲线往上 → 越做越赚
- **垂直数据飞轮 + 第三方 API + 按结果收费**：虽然不拥有成本曲线，但数据飞轮带来的结果质量优势可以支撑溢价 → 客户愿意多付钱因为你比别人准
- **纯工程封装 + 第三方 API + 按结果收费**：利润空间被两头挤压 → 基模涨价你遭殃，客户压价你也遭殃

---

**其他风险信号**：
- 纯 seat-based 定价 → AI 压缩 seat 数 → 收入天花板下降
- 免费用户过多无法变现 → 成本线性增长，收入非线性
- AI 收入 proof 不足 → 有功能无付费，attach rate 未验证
- 无多年合同 → 客户随时可流失（且"按结果付费"天然倾向于短期关系）

**打分标准**：

- **5 分**：双重错配——自有模型无 + 按结果收费 + 成本结构不可控。客户多用你就多亏，基模涨价直接吞掉毛利。无清晰盈利路径
- **3-4 分**：存在明确风险——如第三方 API + 按结果收费但尚未验证利润空间，或 seat-based 模式面临 AI 压缩 seat 数的压力
- **1-2 分**：风险可控——自有模型或深度微调实现成本端规模经济，或垂直数据飞轮支撑的溢价足以覆盖 API 成本

**关键追问**：
- "你拥有你的成本曲线吗？——如果基模 API 明天涨价 30%，你的毛利还剩多少？"

## 燃料类型速查：什么在燃尽 vs 什么在复利

| 会燃尽的燃料 ❌ | 随时间复利的燃料 ✅ |
|:---|:---|
| 提示词优化 | 专有数据飞轮（闭环） |
| 微调模型 | 工作流深度嵌入 |
| UI/UX 设计 | 分销网络与品牌信任 |
| 通用模型调用 | 合约结构与多年合同 |
| 功能优势 | 合规认证（受监管行业） |
| "用最好的模型" | 生产环境可靠性记录 |
| API 成本优势（来自基模降价） | 自有模型的成本端规模经济 |

**判断标准**：如果你的核心差异化是左边这列的任何一项——你就是站在基模的能力缺口上。缺口一填，你就坠落。右边这列的共同特征：它们的价值不依赖于基模的缺口，而是**随着时间复利增长**。基模越强，这些积累反而越值钱——当所有人都能调用同样强大的基模时，差异化的唯一来源只剩下这些"慢变量"。

## 行业特定关键追问

1. "你的核心差异化在左边那列（会燃尽）还是右边那列（随时间复利）？如果全是左边，你还有多少时间？"
2. "你 Day one 就在获客收钱吗？还是还在打磨产品等 PMF？——基模不等你，窗口不等你，客户不等你"
3. "你的早期付费客户在产品里留下了什么？——他们的 workflow 痕迹、定制配置、历史数据，换一个竞品要重来多少？"
4. "你拥有你的成本曲线吗？——收入按什么收，成本按什么付，两者同一条曲线吗？如果基模 API 涨价 30%，你毛利还剩多少？"
5. "客户签的是多年合同还是月付？如果是月付，凭什么认为他们下个月不会换？"
6. "你的产品是 system-of-record 还是 tool？——tool 可以换，record 换不了"
7. "AI 功能有没有体现在付费 attach rate 和 ARPU 提升上？——有功能无付费 = 成本中心，不是收入引擎"
8. "你的定价模式跟成本结构对齐吗？——按结果收费但按 token 付成本，中间的利润空间是结构性的还是运气？"
9. "如果 OpenAI/Anthropic 6 个月内发布你的原生版本，你哪些客户会走、哪些会留、为什么？"
10. "你的数据飞轮闭环了吗？——有数据 ≠ 有飞轮，数据必须产生改善信号才叫燃料"
